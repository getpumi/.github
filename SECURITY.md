# Security policy

## Reporting a vulnerability

Do not report a vulnerability in a public issue, pull request or discussion.

Report it privately through GitHub: open the repository's **Security** tab and choose **Report a vulnerability**. This uses GitHub's private vulnerability reporting, which is turned on in every public getpumi repository. Only you and the maintainers can see the report.

Include what you can of the following:

- the affected repository, component and version or commit;
- what an attacker can do, and under what conditions;
- the steps or code needed to reproduce the problem.

A maintainer will acknowledge the report, work with you on a fix in a private advisory, and publish the advisory, with a CVE where one applies, when a fixed release is available. You will be credited in the advisory unless you ask not to be.

## Supported versions

Security fixes are made for the latest two minor versions of Pumi. Older versions do not receive fixes.

Pumi has no release yet. Until the first release, fixes are made on the main branch only.
