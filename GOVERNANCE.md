# Governance

This file describes how decisions are made in the Pumi project and how people become maintainers. It applies to every repository in the getpumi organization unless a repository has its own GOVERNANCE file.

## Maintainers

A maintainer can review and merge pull requests, triage issues and security reports, and take part in project decisions.

## How decisions are made

Decisions are made by lazy consensus. A proposal is made in an issue or a pull request. If no maintainer objects within a reasonable time, the proposal is accepted. A maintainer who objects explains why and, where possible, suggests a change that would remove the objection.

When maintainers cannot reach consensus, Michael decides until a steering group exists.

Design decisions are recorded as numbered decision records in [getpumi/design](https://github.com/getpumi/design/tree/main/decisions).

## Becoming a maintainer

A person becomes a maintainer by nomination.

1. A maintainer nominates a person who has made sustained contributions to the project, by opening an issue in [getpumi/design](https://github.com/getpumi/design) that names the person and links to their contributions.
2. The nomination is accepted by lazy consensus: if no maintainer objects within two weeks, it passes.
3. Until a steering group exists, Michael can veto a nomination.
4. The new maintainer is added to the table above by pull request.

## Changes to this file

Changes to this file are made by pull request and follow the decision process above.
